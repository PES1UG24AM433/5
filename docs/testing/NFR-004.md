## What was checked

- Reviewed current route logs after issue #35 / PR #66: raw `error.message` logging was removed, but operational logs were generic and successful order lifecycle events were missing.
- Added JSON audit records with ISO-8601 UTC timestamps for order creation, cancellation, staff status changes, idempotency replay, and order-operation failures.
- Included order ID, actor type, status transition, and safe error name/code where applicable. Log construction uses an allowlist and never serializes request bodies or arbitrary error messages.
- Generated real create/status/cancel events through the route integration test against the isolated MongoDB database. Tested creation, status-update, and cancellation failure logging with simulated errors containing password/token-like text.

## Redacted sample output

```json
{"timestamp":"2026-11-16T04:12:19.165Z","event":"order.created","orderId":"<order-id>","actorType":"student"}
{"timestamp":"2026-11-16T04:12:19.474Z","event":"order.status_changed","orderId":"<order-id>","actorType":"staff","previousStatus":"Placed","newStatus":"Completed"}
{"timestamp":"2026-11-16T04:12:19.522Z","event":"order.cancelled","orderId":"<order-id>","actorType":"student","previousStatus":"Placed","newStatus":"Cancelled"}
{"timestamp":"<ISO-8601 UTC timestamp>","event":"order.creation_failed","actorType":"student","errorName":"Error","errorCode":"TEST_FAILURE"}
```

The last event is from a test-injected failure; its message and request payload are intentionally omitted.

## Sensitive-data review

Automated tests confirm that password, token, request-body, and raw error-message fields are not emitted. The allowlisted log fields are operational identifiers and state transitions only; no student name, email, password, authorization header, token, or order-item payload is logged. Error logs retain an error class and bounded code for diagnosis.

The records are JSON lines written to the backend process stdout. This check confirms event generation and output format; production log aggregation, retention, access authorization, and tamper protection must be provided by the deployment platform and were not verified.
